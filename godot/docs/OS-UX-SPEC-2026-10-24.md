# Tablet OS, notifications and flight HUD: UX spec and asset handover (lane osui)

Status: 2026-10-24, Claude lane `osui` (branch `lane/osui`). Audience: DSH session B, who builds it in code.
This document is written so that someone who has not designed an Android UI before can build it. Every number is
given in **dp** (density-independent pixels). In this game **1 dp = 1 logical pixel at the 1280 x 720 canvas**, so in
GDScript multiply by `u` (`u = viewport_height / 720.0`, the helper `PhoneOS._compute_u()` already exists on
`lane/notify`). Never mix dp and raw pixels in one helper.

It builds on, and where they disagree replaces, `docs/ANDROID-OS-UI-SPEC-2026-11-15.md` and
`docs/ANDROID-UI-PASS-2026-11-15.md` (both on `lane/notify`). Those files describe what exists in code today; this one
describes the target and gives the art for it.

**Look at the pictures first.** Everything below is drawn in the mock renders, and every mock is built only from the

### 1.3 Shape, elevation, state layers

| Token | dp |
|---|---|
| corner extra-small | 4 (snackbar, menu, tooltip, text field) |
| corner small | 8 (chips, map POI label plates) |
| corner medium | 12 (cards) |
| corner large | 16 (FAB, nav/rail indicator) |
| corner extra-large | 28 (dialogs, sheets, shade, drawer panel, notification group 24) |
| full | height / 2 (buttons, search bars, QS tiles, switches) |

Elevation is shadow plus tone. Level 1: 1 dp offset, 1.5 dp blur, black 30 percent (cards). Level 2: 2/3/30 percent
(menus, map floating controls). Level 3: 4/5/32 percent (FAB, dialog, heads-up). Godot `StyleBoxFlat`:
`shadow_size = blur`, `shadow_offset = (0, offset)`, `shadow_color = Color(0,0,0,alpha)`.

State layers (put a second StyleBoxFlat with the content colour over the container): hovered 8 percent,
focused/pressed 10 percent, dragged 16 percent. Focus ring: 3 dp, `secondary` colour, 2 dp outside the shape (the
component PNGs include it). Disabled: container = on-surface at 12 percent, content = on-surface at 38 percent.

### 1.4 Motion (Material 3 easing)

| Use | Duration | Godot Tween |
|---|---|---|
| Press ripple / state layer | 150 ms in, 150 ms out | `TRANS_SINE, EASE_OUT` |
| Small toggles (switch knob, QS tile colour, chip) | 150-200 ms | `TRANS_CUBIC, EASE_OUT` |
| Enter (sheet up, shade down, drawer open, dialog) | 250-300 ms | emphasized decelerate: `TRANS_QUINT, EASE_OUT` |
| Exit | 150-200 ms | emphasized accelerate: `TRANS_QUINT, EASE_IN` |
| App open from icon (container transform) | 300 ms | `TRANS_QUINT, EASE_OUT`; icon rect -> app rect, app fades in from 30 percent |
| Heads-up in / out | 250 / 200 ms | slide 24 dp down + fade |
| Snackbar | 250 in, 4 s hold, 150 out | slide up 16 dp + fade |

Robert is dyslexic: no timers or countdown UI, and nothing auto-dismisses that he has to read in time except
heads-up banners, which always remain in the shade.

## 2. App icons (request 1, 8 and A)

### 2.1 Why the drawer "got worse", and the fix

On `lane/notify` the drawer cells are 120 dp wide and the kit icon is drawn with a `TextureRect` that stretches to the
cell (see `docs/realism/android_ui/01_app_drawer.jpg`: every icon is 120 x 64, horizontally squashed). That, plus the
painted, grained, shadowed kit tiles at drawer size, made the set look muddy. Fix both:

1. **Never stretch an icon.** Every icon node is a square `TextureRect` with `expand_mode = EXPAND_IGNORE_SIZE`,
   `stretch_mode = STRETCH_KEEP_ASPECT_CENTERED`, `custom_minimum_size = Vector2(s, s)` and
   `size_flags_horizontal = SIZE_SHRINK_CENTER`. The cell is wider; the icon is not.
2. **Use the new Material 3 adaptive set** (`assets/ui/osui/icons/circle/`): flat vector foregrounds in the field-kit
   palette on a gentle two-stop gradient, inside the Android 72 dp circle mask; no grain, no baked shadow. They are
   rendered natively at each size (never downscaled). The old kit tiles stay in `assets/ui/tablet/icons/` and are no
   longer used by the launcher.

### 2.2 Geometry (Android adaptive icon)

- Canvas 108 x 108 dp; visible mask 72 dp (circle by default, `squircle` set as the Settings > Wallpaper & style >
  App shape alternative); foreground art inside the 66 dp safe circle, main mass on the 48 dp keyline.
- Layers: `icons/layers/<app>_bg` (full bleed), `_fg` (transparent), `_mono` (white silhouette with details cut out).
  The composited files are what B should load; the layers exist for parallax or for a future icon-shape setting.
- Size to load, by on-screen size in physical pixels (the export bigger than or equal to the display size):
  48 (status/notification slots use `mono`), 64, 96, 128, 192. At 1080p a 60 dp home icon is 90 px: load 96.
  At 4K load 192. Write `TabletIcon.pick(size_px) -> int` returning the first of [48, 64, 96, 128, 192] that is
  `>= size_px`, else 192.
- Themed icons: when Settings > Wallpaper & style > Themed icons is on, load `icons/themed/dark/<px>/<app>.png`
  (or `light`). Default off; it is the Android 13+ look Robert asked to have available.
- Notification and status-bar icons: `icons/mono/<px>/<app>.png`, tinted with `modulate` to on-surface.

### 2.3 Badges and dots

Large badge: 16 dp tall, 8 dp radius, `badge` colour, label-small white, min width 16, centred on the icon's
top-right at (x + 0.86 s, y + 0.14 s). "9+" cap. Small dot: 9 dp circle at the same point. DroneBudz shows the unread
count; Jobs and Casebook use the dot when something changed; the badge and the status-bar notification icons read the
same source so they always agree. Art: `components/<theme>/badge_large_default.png`, `badge_small_default.png`.

### 2.4 Which icons were missing beyond appui2 (request 8), now made

appui2 delivered 14 painted phone icons plus app glyphs, badges and Casebook/Map kits. Still missing, and now built:

1. **A Material 3 adaptive launcher set** for all 17 apps in three forms (circle, squircle, themed light/dark) plus
   monochrome: the 7 game apps, Settings, Facade Apps (store), Package installer, Weather, Camera, Clock, Files,
   Phone, Field Notes, Recents. (`icons/`)
2. **System glyphs** at stock Android fidelity (Material Symbols, Apache-2.0): Quick Settings tiles (Wi-Fi/drone link,
   Bluetooth, DND, flashlight, battery saver, rotation, screen record, airplane, night, thermal), status bar
   (signal, Wi-Fi, battery levels, DND, alarm), navigation, Settings rows (12 categories), notification actions
   (reply, send, mark read, expand), store (install, download, update, delete, shield, privacy), lock screen (lock,
   fingerprint, flashlight, camera), map controls (my_location, navigation, layers, explore, zoom). (`system/`)
3. **Flight HUD icon set** (56 glyphs, 4 states, 6 sizes), including the thermal and night-vision buttons and the
   key-hint versions. (`hud/`)
4. **Map symbology**: 45 POI glyphs (Maki/Temaki CC0) in 11 category markers, launch-site and dropped pins, drone
   arrow, my-location puck with heading cone and accuracy ring, compass, zoom, recentre, layers. (`map/`)
5. **Per-app splash icons, header banners and empty-state illustrations** for all 17 apps. (`apps/`)
6. **Component art** for every Material 3 component listed in section 9. (`components/`)

Not made (honest): Lucide/Tabler/Phosphor files are downloaded as a reserve but not used in shipped art; the
Material set covered every system need.

## 6. Status bar, navigation and Back (request B)

### 6.1 Status bar (28 dp tablet, 32 dp phone)

Left: clock label-large 14 sp at x 16; then up to 4 notification icons (`icons/mono/48/<app>.png` drawn at 16 dp,
6 dp gap); a fifth or more becomes a 5 dp dot. Right, right to left: battery percentage label-large, battery glyph

then DND `do_not_disturb_on_fill` when DND is on, alarm when an alarm is set. White over the wallpaper, on-surface in
apps. The tablet battery is the tablet, not the drone.

### 6.2 Navigation: gesture by default

Gesture pill 108 x 4 (section 3.1). Swipe up from the bottom 24 dp: Home. Swipe up and hold 300 ms: Recents. Edge swipe
from left or right 24 dp zone, 32 dp threshold: Back. Keyboard: Esc = Back, Tab = put the tablet away, N = shade.
An optional 3-button bar (48 dp, `system/48/arrow_back`, `home_fill`, `recents` mono) is a Settings > System >
Gestures option, off by default.

### 6.3 What Back does (Robert's rule)

| Where | Back / the HUD's top-left back chevron |
|---|---|
| **Flight HUD** | The top-left back chevron (`hud/glyph/back`) **opens the tablet on the Home screen (desktop)**, exactly like pressing Home on a real tablet. It no longer opens the pause menu. The pause / settings menu moves to the `more` (three dots) button at the top right of the top bar. Keyboard Tab keeps toggling the tablet. |
| Inside an app (top app bar back arrow, edge swipe, Esc) | Up one level inside the app; at the app's root, go to Home. |
| Home | Nothing (Android). Tab or the gesture pill swipe-down puts the tablet away and returns to the flight. |
| Drawer, folder, Recents, shade, dialog, sheet | Close that surface only. |

The HUD back chevron shows a 4 dp `badge` dot at its top-right when there are unread notifications, so the player
knows there is something on the tablet. The separate tablet and bell discs that `lane/notify` added to the right-hand
column are removed (section 11).

## 7. Notifications: shade, Quick Settings, heads-up, lock screen (requests 2, 7, B)

### 7.1 Opening the shade: hover hint and pull-down (desktop and touch)

The shade can be opened from anywhere: home, an app, or the flight HUD. Mock: `64_hud_shade_pull_states.jpg`.

1. **Hover hint (mouse):** when the pointer is within 6 dp of the top edge of the window for 250 ms and no button is
   held, fade in `hud/pill/shade_hint_2x.png` (160 x 40 dp, centred) over 150 ms; fade out 150 ms after the pointer
   leaves the top 80 dp. On home and in apps it sits at y 0 (over the status bar); in flight it sits at y 40, directly
   under the HUD top bar, so it never covers telemetry text. It is drawn on the system-UI layer, below the shade. Click
   the hint, or press and drag down from the top 24 dp (or from the hint), to pull.
2. **Pull (mouse drag or touch swipe from the top 24 dp):** the sheet follows the pointer 1:1 (its bottom edge = pointer
   y), clamped to the sheet's full height; the scrim alpha = 0.32 x progress. While pulling, the HUD keeps running
   (the sandbox must keep flying), and HUD buttons under the sheet stop receiving input.
3. **Release:** if progress > 0.4 or the fling velocity > 800 dp/s downward: settle open (280 ms, emphasized
   decelerate). Otherwise snap back (200 ms, emphasized accelerate).
4. **Open:** full shade (7.2). The HUD top bar is covered by the sheet; nothing on the HUD moves.
5. **Dismiss:** swipe up on the sheet or its handle (same 0.4 rule), Back/Esc, N, tap the scrim, or tap the hint
   again. Dismiss is 200 ms.
6. **Coexistence with the HUD top bar:** the top 24 dp grab zone sits on top of the 40 dp HUD top bar. To keep the
   HUD's back chevron and `more` button usable, the grab zone excludes their 48 x 40 dp rects (left 0..56, right
   width-56..width). A tap (press and release within 8 dp) inside the grab zone passes through to the top bar; only a

## 15. Honest limits

- The mocks are rendered from SVG; Godot will rasterise text and anti-alias slightly differently. Sizes, colours and
  positions are exact, not the font hinting.
- The HUD mocks use a clean frame captured from the game with the HUD hidden; thermal and night pictures are a simple
  luminance colour-map of that frame, not the game's thermal/night shaders.
- Wallpaper is still the 1024 x 683 public-domain photo (soft at 1080p); the lock screen and home make that visible.
- The map reference renderer reads the world data from the `AeroSim-notify` checkout (main does not have the roads
  and world files yet). After `lane/notify` merges, `gen_map.WORLD` should point at `godot/assets/world`.
- Lucide, Tabler and Phosphor icons are downloaded as a reserve only; nothing shipped uses them yet.
- The HUD glyphs with letters (AF, MF, WB, ISO, HD, H, mode letters) contain `<text>` in their SVG sources; use the PNGs
  in Godot.
- Not built: page-2 widgets art, wallpaper picker, Material You dynamic colour, a dedicated ThermalSight icon,
  per-app interior layouts beyond what the notify spec already covers.
