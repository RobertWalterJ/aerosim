# Rules for every Claude art lane (shared by all briefs)

Photoreal is the standing direction: believable proportions and scale, photographed CC0 PBR textures where they help (record source, author and licence in godot/assets/textures/README.md), light checked at golden hour and overcast, assets that are useful and drop in without code changes. Quality over quantity.

Process: worktree AeroSim-<lane> on branch lane/<lane> from current main; commit only your own files (never whole-tree add; the AeroSim repo root has unrelated web-repo changes); gate with godot/tools/gate.ps1 -Tag <lane> (not while another session is mid-gate); merge main into your branch first, then merge to main only under RWJ Coding Projects/AeroSim-merge.lock (absent = free), never with an open conflict; do not push. One Godot at a time across sessions via RWJ Coding Projects/godot-run.lock (create before running Godot, delete after, wait if under 10 minutes old; tools/blender/godot_locked.sh helps). Never taskkill by image name. Blender 4.2.3 portable: RWJ Coding Projects/_tools/blender-4.2.3-windows-x64/blender.exe, scripts in godot/tools/blender/ (see the existing build_*.py). Follow conventions in game/README-models.md (add a section named after your lane, never "Batch N"); existing lanes: farm, vehicles, animals, people, drones, buildings, tablet UI (assets/ui/tablet).

Verification: LOOK at every image yourself before claiming done. Check orientation (roofs up, text not mirrored, normals outward, nothing floating, correct forward axis) and add automated checks where geometry is involved. Produce a views contact sheet AND a textures-used sheet (labelled swatches, source, licence) in docs/realism/models/ named <lane>_final_views.jpg and <lane>_final_textures.jpg. Post [STATUS CLAUDE] on RWJ Coding Projects/AeroSim-BOARD.md and report with sheet paths and honest shortfalls.
